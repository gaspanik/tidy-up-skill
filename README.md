# tidy-up — Auto Layout Restructuring for Figma

Register this skill in Figma's custom skill feature, select a manually-positioned frame or component, and run it from the chat. It analyzes the selection visually and structurally, then rebuilds it in place as a clean, auto-layout-based hierarchy — normalized spacing and semantic layer names — while keeping the original visual appearance intact.

---

## What this is

Designs built by dragging elements into place — whether by hand or generated by an AI design agent — tend to accumulate the same problems: asymmetric margins, inconsistent gaps between similar elements, generic layer names (`Frame 12`, `Rectangle 3`), and no auto layout at all. That makes the file fragile (content changes break the layout) and hard to hand off to a design system or to code.

This skill fixes that without changing how the design looks. It captures a "before" screenshot and a per-element spacing map first, then tells apart two kinds of irregularity: macro-level layout rhythm (the gaps between sections, the padding inside them) which it preserves and rounds onto a 4px grid, and micro-level sloppiness (off-center button text, a card's contents sitting a couple pixels off from its neighbors) which it lets auto layout's own alignment fix instead of faithfully reproducing. It rebuilds the whole thing as a nested auto-layout structure — moving nodes into new parent frames rather than recreating them — then iterates a screenshot-compare-fix cycle until the macro-level result matches the original.

It also scans the file for existing variables and styles and reports what it finds, but it doesn't bind them itself — binding is a separate, heavier pass better handled by a dedicated skill like `figma-tokenize` afterward, so `tidy-up` stays fast for its own job: structure and spacing.

```
Select a manually-positioned frame or component
        │
        ▼
Capture "before" screenshot + per-element spacing map
  → distance from each edge, gaps between siblings
        │
        ▼
Check for existing variables/styles (report only, no binding)
        │
        ▼
Normalize spacing: preserve macro-level rhythm (4px grid),
correct micro-level misalignment (auto layout alignment)
        │
        ▼
Rebuild hierarchy with appendChild (never remove())
  → convert to auto layout, set FILL/HUG sizing
        │
        ▼
Rename every layer to a semantic kebab-case name
        │
        ▼
Screenshot again → compare against "before" → fix → re-verify
  (repeat until the macro-level result matches)
```

## Scope

- **Operates on a selection.** Target one or more manually-positioned frames or components — this skill doesn't generate new designs from scratch.
- **Preserves the original look at the macro level.** Section-level gaps and padding are kept (rounded onto a 4px grid); only micro-level sloppiness (off-center text, a few stray pixels between near-identical elements) is corrected via auto layout's own alignment, inferred as CENTER unless the original position is clearly biased to one side.
- **Checks variables, doesn't bind them.** If the file already has variable collections or styles, it reports what it found in the final summary and recommends running a dedicated skill (e.g. `figma-tokenize`) afterward — binding was moved out of this skill because doing it inline made a single run noticeably heavier.
- **4px-grid normalization, not forced rounding.** Asymmetric or inconsistent spacing gets rounded to the nearest multiple of 4, but values that look clearly intentional (e.g. exactly 15px) are left alone.
- **Never deletes content.** Existing text and shape nodes are moved into new structural frames via `appendChild`; only redundant background rectangles (once their fill is transferred to the parent frame) are removed.
- **Verifies iteratively.** After rebuilding, it screenshots the result, compares it against the "before" screenshot, and repeats a fix-and-verify cycle until the macro-level layout matches — it doesn't report done after a single pass.
- **Multi-selection supported.** Select more than one frame or component and it processes them in the same pass.

## Example output

After rebuilding, the skill reports what changed alongside a before/after screenshot:

```
Restructure complete:

- Rebuilt as auto layout: root (VERTICAL) → header, hero-section,
  card-grid, footer
- Preserved macro-level spacing: section gaps 23px/25px → 24px,
  card gaps 12–16px → 16px (rounded to the 4px grid)
- Corrected micro-level misalignment: button text re-centered,
  3 card titles were off by 4–8px from a shared left edge → now
  uniform padding
- Renamed 14 layers (Frame 12 → hero-section, Rectangle 3 →
  card-background, Text 7 → hero-title, ...)
- Existing variables found: 12 color variables, 5 spacing
  variables — not bound by this skill; run figma-tokenize next
  if you want them bound
- Visual comparison (2 fix-and-verify passes): macro-level
  spacing matches the original, micro-level alignment cleaned up
```

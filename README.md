# tidy-up — Auto Layout Restructuring for Figma

Register this skill in Figma's custom skill feature, select a manually-positioned frame or component, and run it from the chat. It analyzes the selection visually and structurally, then rebuilds it in place as a clean, auto-layout-based hierarchy — normalized spacing, semantic layer names, and (optionally) variable bindings — while keeping the original visual appearance intact.

---

## What this is

Designs built by dragging elements into place — whether by hand or generated by an AI design agent — tend to accumulate the same problems: asymmetric margins, inconsistent gaps between similar elements, generic layer names (`Frame 12`, `Rectangle 3`), and no auto layout at all. That makes the file fragile (content changes break the layout) and hard to hand off to a design system or to code.

This skill fixes that without changing how the design looks. It looks at a screenshot plus the raw layer tree to understand which elements form logical groups (headers, cards, sections), records the original spacing precisely, normalizes it onto a 4px grid, and rebuilds the whole thing as a nested auto-layout structure — moving nodes into new parent frames rather than recreating them, so nothing is lost in the process.

```
Select a manually-positioned frame or component
        │
        ▼
Screenshot + layer tree analysis
  → infer semantic groups (header / card / section / footer)
  → scan for existing variables & styles in the file
        │
        ▼
Record & normalize original spacing to a 4px grid
        │
        ▼
Rebuild hierarchy with appendChild (never remove())
  → convert to auto layout, set FILL/HUG sizing
        │
        ▼
Rename every layer to a semantic kebab-case name
        │
        ▼
Bind variables/styles per chosen strategy
  (nearest match / create new / skip)
        │
        ▼
Screenshot again + verify appearance is preserved
```

---

## Scope

- **Operates on a selection.** Target one or more manually-positioned frames or components — this skill doesn't generate new designs from scratch.
- **Preserves the original look.** The goal is structural cleanup, not a redesign — margins, gaps, and colors are normalized/tokenized, never changed in a way that alters the visual result.
- **Asks before binding variables.** If the file already has variable collections or styles, it presents what it found and lets you choose: bind to the nearest existing match, create new variables for unmatched values, or skip binding entirely and leave values hardcoded.
- **4px-grid normalization, not forced rounding.** Asymmetric or inconsistent spacing gets rounded to the nearest multiple of 4, but values that look clearly intentional (e.g. exactly 15px) are left alone.
- **Never deletes content.** Existing text and shape nodes are moved into new structural frames via `appendChild`; only redundant background rectangles (once their fill is transferred to the parent frame) are removed.
- **Multi-selection supported.** Select more than one frame or component and it processes them in the same pass.

  card-grid, footer

  card gaps 12–16px → 16px
- Renamed 14 layers (Frame 12 → hero-section, Rectangle 3 →
  card-background, Text 7 → hero-title, ...)

  existing Color variables, 3 spacing values left hardcoded
  (no match within tolerance)

  or spacing
